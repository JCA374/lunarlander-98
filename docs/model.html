The model

What the pilot is, how it learns, and how it changes over time. This page grows as the project goes on.

Film: how the lander learned (the bake-off, explained)

About 13 minutes, narrated. Real flights with the wind drawn (blue: the true wind, hidden from the pilot; orange: the pilot's own estimate), the network firing live, the three training methods compared, and why each test exists.

1. A pilot is a function from 16 numbers to 4 choices

Every 1/50 of a second the lander must choose one of four actions: do nothing, fire the left engine, fire the main engine, or fire the right engine. The pilot is a neural network: a function that takes the 16 input numbers and returns four scores, one per action. It fires the action with the highest score.

The network here is a multilayer perceptron with two hidden layers of 128 units. Each unit computes a weighted sum of the numbers coming in, adds a bias, and squashes the result with tanh into −1…1. With 16 → 128 → 128 → 4 it has about 19,000 weights. Before the inputs go in, each one is shifted and scaled to roughly −1…1 (normalisation), using averages measured on real flights, so no input dominates just because of its units.

inputs (16) ──► 128 tanh units ──► 128 tanh units ──► 4 scores ──► pick the largest
  x, y, vx, vy, angle, …, wind estimate           nothing / left / main / right

2. Three ways to find good weights (the bake-off)

Copy a teacher (behaviour cloning). Fly the hand-written pilot, record (inputs, its action) at every step, and train the network to predict the action, like a classifier. Then DAgger: let the student fly, and ask the teacher what it would have done in the states the student's own mistakes lead to. The copy reaches the teacher's level (83.5% vs 85.9% on the same 1,000 flights) but not beyond it.

Reinforcement learning (PPO). The network outputs probabilities instead of a hard choice, so it can explore. After each batch of flights, every action is judged: did things go better or worse than expected after it? A second network, the critic, learns what "expected" is (the value of a state). Actions that turned out better than expected become a little more likely, worse ones a little less, and a clip keeps each update small (that is the "proximal" in PPO). It learns from every one of the hundreds of steps in a flight, not just from one number per flight.

Evolution strategies (ES). Make 40 slightly perturbed copies of the network, fly each on the same 32 flights, and move the weights toward the copies that landed more often. Simple and robust, but it only learns from one number per flight per copy.

Which one is used is decided by a bake-off with the same CPU budget for each; see the Log.

3. What it is paid for

The game's own score already guides a lander: points for moving toward the pad and slowing down, small costs for firing engines, −100 for a crash, +100 for coming to rest. The old project found a trap here: the score also pays for saving fuel, so a pilot can earn more points while landing less often. So on top of the score this project pays +200 for coming to rest between the flags and −100 for coming to rest outside them or timing out. The goal measure itself is never the score: it is only "came to rest between the flags".
