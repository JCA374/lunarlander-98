Speed

The laptop, where the time goes, and what each optimisation bought, measured end to end.

The machine

CPUIntel Core i5-8250U, 4 cores / 8 threads, 1.6 GHz base
Memory7.6 GB RAM, 4 GB swap
GPUIntel UHD Graphics 620: no CUDA, so everything runs on the CPU
SoftwarePython 3.12, PyTorch 2.15 (CPU), gymnasium 0.29.1 + Box2D, numpy 1.26

Plan for a CPU: small networks, many flights in parallel (8 worker processes, one per thread), the network's forward pass done in numpy inside the workers, and the PPO update in PyTorch between batches.

First measurements (30 Oct)

WhatSpeed
Hand-written pilot, 8 processes, reference env80 flights in 1.0 s (≈ 40,000 steps/s)
PPO rollouts + update, 8 workers × 8 flights, 2×128 network16,384 steps per 0.8 s iteration (≈ 20,000 steps/s, ≈ 70 M steps/hour)

From the old project: per simulated step, Box2D itself took 1.5 µs of 117 µs; the rest was Python glue. A native, vectorised re-implementation is the big possible win, but only once the method works, and only for training: every check and the goal test stay in the reference env.
